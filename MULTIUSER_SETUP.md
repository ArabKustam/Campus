# Аккаунты, личные подключения и размещение

Опубликовано: https://campus-planner.mymemory9.workers.dev

## Первый запуск

1. Создайте свой аккаунт сайта. Пароль — минимум 12 символов; сохраните его в менеджере паролей.
2. На этом компьютере коннектор уже настроен на опубликованный адрес. Для последующего запуска из проекта: `npm run connector`.
3. На другом компьютере скачайте архив в Настройки → Telegram/WhatsApp → «Как запустить коннектор». Распакуйте, выполните `npm ci`, затем `npm start`.
4. Нажмите «Показать QR», отсканируйте QR в мессенджере и выберите группы. Для Telegram нужны собственные API ID/API Hash с my.telegram.org/apps и облачный пароль, если он включён.
5. В «Люди и роли» создайте карточки и привяжите отправителей из двух мессенджеров к одной карточке. Не объединяйте людей только по совпадению имени.

## Что реализовано

- Регистрация, вход, выход, изменение пароля с отзывом остальных сеансов, отзыв ключей коннекторов. HttpOnly/SameSite cookie; на HTTPS используется Secure. Ограничение попыток входа по логину и IP, проверка Origin и служебного заголовка для изменений.
- Облачная D1 хранит аккаунты и хеши сессий/ключей. Каждому аккаунту соответствует отдельный SQLite Durable Object. Через интерфейс D1 используются прежние проверки и обработчики расписания, заданий и AI. Пользователь не выбирает ID чужого рабочего пространства.
- Вложения до 20 МБ хранятся порциями в личном рабочем пространстве. Прочитать их можно только через авторизованный API владельца; браузерное кеширование отключено. R2 для этой конфигурации не требуется.
- Реальные локальные библиотеки Telegram MTProto и WhatsApp Web. Демонстрационные bot/mock маршруты исключены из рабочего приложения.
- На сервер передаются метаданные групп для выбора, затем только выбранные сообщения. Проверка разрешённых чатов выполняется до отправки и при приёме. Исходный полный payload мессенджера на сервер не отправляется.
- Ограничение истории: с 30.08.2026 00:00 Asia/Almaty включительно. Старые сообщения и цитаты без подтверждённой даты не входят в AI-контекст. История WhatsApp ограничена доступностью данных на связанном устройстве.
- Карточки людей: имя, никнейм, роль и ручные связи provider + sender ID. Эти сведения передаются AI как контекст. Флаг доверия не берётся из сообщения. Автоприменение изменений расписания дополнительно требует доверенного отправителя и включённой настройки.
- Массовые отмены, явные шутки и последующее опровержение автора не применяются автоматически. Нельзя гарантировать распознавание любой иронии.
- ADD_LESSON создаёт разовую СРС/консультацию с известными предметом, датой и временем. Проверяются конфликты. По умолчанию действие подтверждается в «Обработке». Явно написанный единственный интервал времени дополнительно извлекается без угадывания длительности.

## Ограничения и сохранность данных

- Личный коннектор должен работать на компьютере. Он не является круглосуточным облачным мостом. Телефон/браузер могут потребовать подтверждения входа и разрешения доступа к локальной сети.
- Реальный QR WhatsApp получен при проверке; вход в личный аккаунт и получение его истории требуют сканирования владельцем. Telegram с личными реквизитами пользователя не проверялся.
- Выбранные тексты передаются Cloudflare Workers AI. Изоляция от других пользователей сайта не означает недоступность этих выбранных данных владельцу инфраструктуры или провайдеру AI.
- Сторонний WhatsApp Web коннектор зависит от изменений WhatsApp. Для Telegram применяются ограничения API, включая условия использования данных для AI: https://core.telegram.org/api/terms.
- Используются бесплатные квоты Cloudflare; безлимитная работа не обещается. Объём хранилища и AI ограничен тарифом аккаунта. Платные сервисы не включались.
- Старый локальный D1 не удалялся и не выгружался в интернет. Его личные записи автоматически не присваиваются первому зарегистрировавшемуся пользователю. Новые аккаунты получают отдельную копию исходного шаблона расписания.

## Для разработчика

- `npm run dev` — локальный сайт и Worker.
- `npm run connector` — локальный коннектор. Адрес разрешённого сайта задаётся в `bridge/.env`.
- `npm run deploy` — сборка клиента и публикация через `wrangler.production.jsonc`.
- Перед изменением схемы добавьте миграцию и соответствующий шаг в `worker/workspace/object.ts`. Реестр аккаунтов и рабочие пространства мигрируются отдельно.
- `.data`, локальные сессии и реальные ключи не входят в скачиваемый архив. Не помещайте их в public/dist или в репозиторий.
